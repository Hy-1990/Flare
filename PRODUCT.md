# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Independent creators turning a supplied script into a short film. The user primarily works in a full desktop browser window and evaluates the working application there.

## Product Purpose

Flare brings script, storyboard, visual-style references, shot editing, preview and local video export into one local application. Success means the creator can select a production style, edit individual shots, preview and export without losing work.

## Operating Context

Flare is an independent local application. The local app listens on loopback at port 4317. User review precedes any GitHub source upload. Desktop is primary; narrow windows and mobile still require functional, readable controls.

## Capabilities and Constraints

- 99 original upstream styles across15categories, original demo references and production guides;3original Flare styles remain.
  -8upstream styles have basic native animation;91use image-assisted production and require an image per shot before export. Full99original demo engine parity is not implemented.
- Optional DeepSeek planning and shot revision; optional DreamAPI image and voice generation with paid-task confirmation.
- Local MP4, subtitle and storyboard exports; persistence and per-shot undo.
- Chinese/English interface and light/dark/system appearance must remain. UI preferences must not alter scripts, media or film appearance.
- Never execute generated model code, expose stored keys, run unapproved paid tests or push/deploy before explicit user approval.

## Brand Commitments

The name is Flare. The user requested a compact professional film-editing workspace, strong typography and film-led hierarchy. They rejected both previous implementations as generic/AI-looking and reported language-selection misalignment and text occlusion. Those implementations are anti-references, not accepted visual authority. The user chose the Cinematheque program direction on the decision page, then requested further typography/layout refinement within it. The chosen sketch is `.impeccable/mocks/decision/cinematheque.html`.

## Evidence on Hand

Actual starter film, working Canvas previews, original upstream reference posters/guides cached locally, existing editor and export workflows, automated tests. Upstream metadata is MIT; guides and media retain their separate terms. No fictional testimonials, usage metrics or unimplemented capabilities may be added.

## Product Principles

Preserve the creator's content and unfinished edits. Make actual production support and costs explicit. Let real film material carry visual emphasis. Treat user-visible collision and clipping as defects even when whole-page overflow tests pass.
